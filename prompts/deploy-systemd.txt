Deploy my Dulak app on my VPS using systemd (no Docker). Here are
the details:

- SSH: ssh USER@SERVER_IP
- GitHub repo: https://github.com/YOUR_USER/YOUR_REPO.git
- Domain: your-domain.com (or "none" if no domain yet)
- Install path: /opt/dulak
- App port: APP_PORT

Steps:
1. SSH into the server.
2. Install Bun (curl -fsSL https://bun.sh/install | bash).
3. Check if the app port is already in use (ss -tlnp | grep APP_PORT).
   If it is, pick the next available port and use that instead.
4. Clone the repo to the install path.
5. Run `bun install` and `bun run build`.
6. Copy .env.example to .env and change these three lines:
   - PORT=<the port you chose>
   - NODE_ENV=production
   - APP_URL=https://your-domain.com (or http://SERVER_IP:<port> if no domain)
   Leave the rest as-is (DATABASE_PATH is relative, works anywhere).
7. Read the "name" field from package.json — that's the service name.
   Create a systemd unit at /etc/systemd/system/<name>.service that
   runs `bun run src/index.ts` with WorkingDirectory set to the
   install path.
8. Enable and start the service.
9. If the port is not in UFW rules, allow it: sudo ufw allow <port>/tcp.
10. Verify: curl http://localhost:<port>/health should return 200.
11. Save these four lines to a file called `deploy.env` in my local
    project root (NOT on the server) and add it to .gitignore.
    Use the actual values from above (not the placeholders):
    ```
    DEPLOY_SSH=<the USER@SERVER_IP from above>
    DEPLOY_PATH=<the install path from above>
    DEPLOY_SERVICE=<the service name from step 7>
    DEPLOY_PORT=<the port you chose in step 3>
    ```
12. Tell me the status, the port used, and any issues.
